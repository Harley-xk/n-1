# 新模块接入指南

> 本指南是「业务模块从 0 到 1」的标准路径，以样板模块 **demo（示例商品管理）** 为参照沉淀。
> 新业务模块照本文八步执行；每一步的「照抄对照表」给出 demo 中的对应文件。
> 前置阅读：[架构设计](../架构设计.md)、[权限设计](权限设计.md)、[统一响应与异常处理设计](统一响应与异常处理设计.md)。

## 0. 段位登记表

新模块动工前先「领号」——以下四者同构（模块名 / 权限串首段 / 表前缀 / 错误码模块段），登记决定写入模块自己的设计文档：

| 模块 | 注册名 / 权限前缀 | 表前缀 | 错误码模块段 | 种子固定 id 段 |
| --- | --- | --- | --- | --- |
| system | `system:` | `system_` | 001（数值 `100x00yyy`） | `…0001`~`…0041` |
| demo | `demo:` | `demo_` | 002（数值 `200x00yyy`） | `…0051`~`…0063` |
| **下一个模块** | **`<biz>:`** | **`<biz>_`** | **003 起（统一响应设计段位表同步登记）** | **新一段（如 07x），避开已占用段** |

固定 id 形态：`00000000-0000-4000-8000-0000000000xx`（**必须为合法 v4 形态**——version 位不能为 0，否则 DTO 的 `@IsUUID()` 会拒绝）。

## 1. 八步清单

### 第 1 步：设计文档先行

`docs/<模块名>/<功能>设计.md`（中文名），含：需求背景、表设计、接口清单、**本表 0 的段位登记决定**、边界与不做清单。实现偏离设计时先改文档再改代码（[rules/base.md](../../rules/base.md) 第 4 节）。

### 第 2 步：后端模块骨架

新建 `server/src/modules/<biz>/`，`<biz>.module.ts` 装配后在 `app.module.ts` 的 imports 追加一行。

```ts
// 照抄：modules/demo/demo.module.ts
@Module({
  imports: [TypeOrmModule.forFeature([<Biz>Entity])],
  controllers: [<Biz>Controller],
  providers: [<Biz>Service],
})
export class <Biz>Module implements OnModuleInit {
  constructor(private readonly permissionRegistry: PermissionRegistry) {}
  onModuleInit(): void {
    this.permissionRegistry.registerModule({ module: <BIZ>_MODULE_NAME, points: <BIZ>_PERMISSIONS })
  }
}
```

> 依赖方向纪律：业务模块 → system（`@Global` 导出的 `PermissionRegistry` 等直接注入）；system 永不反向 import 业务模块。

### 第 3 步：权限点登记

模块自己的 `permissions.ts`（照抄 `modules/demo/permissions.ts`）：

1. 常量层 `<BIZ>_PERMISSION_CODES`：权限串字面量唯一出处（`<biz>:<域>:<操作>` 三段冒号小写）；
2. 清单层 `<BIZ>_PERMISSIONS: readonly PermissionPoint[]`：code + 中文名（角色分配界面展示用）；
3. `<BIZ>_MODULE_NAME`：注册名，须与权限串首段一致——启动期 fail-fast 校验（首段不符 / 全局重复即拒绝启动），super_admin 经注册表全集自动拥有，**零额外维护**。

Controller 挂 `@RequirePermissions(<BIZ>_PERMISSION_CODES.XXX)`（OR 语义，无注解 = 仅需登录）。

### 第 4 步：错误码段位登记

模块自己的 `error-codes.ts`（照抄 `modules/demo/error-codes.ts`）：领模块段后按子域铺开，数值 = 模块段 × 10⁸ + 子域号 × 10⁵ + 序号（如 demo 商品 `200100000`）。业务抛错一律引用常量：

```ts
throw businessError(DemoErrorCode.PRODUCT_NAME_DUPLICATE.message, { code: DemoErrorCode.PRODUCT_NAME_DUPLICATE })
```

同步动作：[统一响应与异常处理设计](统一响应与异常处理设计.md) 段位表加一行。

### 第 5 步：实体与迁移

1. 实体放 `modules/<biz>/entities/`，**一律继承 `BaseEntity`**（uuid 主键 + 审计自动填充 + 软删）；表名 `<biz>_<域>` 蛇形；唯一索引用部分唯一索引（`WHERE deleted_at IS NULL`，软删行不占位）；
2. DDL 迁移经 `pnpm --filter server migration:generate -- src/migrations/<名称>` 从实体派生（**实体是 schema 唯一事实源**，ADR-005；`DB_SYNC` 已关，迁移是唯一建表通道）；
3. 种子迁移手写（照抄 `DemoSeed`）：固定 id 用模块自己的 constants 文件（与代码同源），时间戳接续现有迁移之后；
4. 建表类型规约（PG 优先）：uuid / boolean / timestamptz / numeric（详见 [架构设计](../架构设计.md)）。

> numeric 金额列注意：PG 驱动读出为 string，`toVo` 统一 `Number()` 转数值出口；真实大金额业务建议全链 string（样板从简未采用）。

### 第 6 步：后端域四件

`modules/<biz>/<域>/` 下三件 + entities 一件（照抄 `modules/demo/product/` 1:1 平移）：

| 件 | 要点 |
| --- | --- |
| `<域>.controller.ts` | `@ApiTags` 中文分组 + `@Controller('<biz>/<域>')`；查询挂 query 权限、写接口挂对应权限 **+ `@OperateLog('<中文名>', '<操作>')`**；**DTO 必须值导入**（`import type` 会擦除元数据，ValidationPipe whitelist 将拒绝全部字段） |
| `dto/<域>.dto.ts` | 单文件收拢：出参 `interface <X>Vo` + 入参 class（Create / Update / Page）；校验注解带中文 message |
| `<域>.service.ts` | 唯一校验（查重排除自身 `Not(excludeId)`）、存在性校验（`getExists` 不存在抛错）、`toVo` 白名单映射 |
| `entities/<域>.entity.ts` | 见第 5 步 |

### 第 7 步：前端三件

| 件 | 照抄 |
| --- | --- |
| `web/src/api/<biz>/<域>.ts`：VO / CreateData / UpdateData / PageParam 类型 + 接口函数（GET 记得 `{ params }` 包装） | `api/demo/product.ts` |
| `web/src/views/<biz>/<域>/index.vue` + `components/<X>SaveDialog.vue`：搜索卡 + 表格卡 + 分页 + 弹窗六件套；字典列 `DictTag`、字典下拉 `DictSelect`；按钮 `v-hasPermi`；时间列 `dateTimeColumnFormatter`；**`defineOptions({ name })` 与路由 name 对齐**（keep-alive 缓存键契约） | `views/demo/product/` |
| `web/src/router/modules/<biz>.ts`：路由 name PascalCase、`meta.permission` 挂 query 权限；在 `router/index.ts` 合并 `layoutChildren` | `router/modules/demo.ts` |

配套登记：`utils/menu-icon.ts` 加图标语义名；`utils/permission.ts` 的 `DOMAIN_LABELS` 加域中文名（角色分配弹窗分组展示）。

### 第 8 步：测试验证与文档回填

1. server 单测（风险分级）：service 唯一 / 存在性等有分支逻辑的必测，controller 薄壳不写（e2e 守护）；测试符号从 `@jest/globals` 显式导入；
2. server e2e：模块装配用例（路由可达、统一响应结构、403、写闭环）；存量权限点数量断言同步（`auth.e2e-spec` 与 `system-extension.e2e-spec`）；
3. 浏览器 e2e：页面验收用例（列表 / 新增编辑删除闭环 / 权限过滤）；
4. `pnpm check` 全绿 + `pnpm --filter server migration:run` 真库跑通；
5. 文档回填：权限设计权限点清单、统一响应段位表、CLAUDE.md 当前状态、`docs/README.md` 索引、规划文档勾选。

## 2. 效果保障（接错即炸）

| 漏错 | 后果 | 保障机制 |
| --- | --- | --- |
| 权限串首段写错 | 权限体系串段漂移 | 启动期 fail-fast（注册表校验拒绝启动） |
| 权限串与已有模块重复 | 全局冲突 | 注册表跨模块查重拒绝启动 |
| 错误码段位撞车 | 排查对读错乱 | 段位表唯一出处 + 常量唯一出处 |
| super_admin 没有新权限 | 超管不可用 | 注册表全集自动扩容，零维护 |
| 忘挂 `@RequirePermissions` | 越权风险 | 接口默认仅需登录（评审项），写接口必挂权限 + `@OperateLog` |
| 路由 name 与页面 name 不齐 | keep-alive 缓存失效 | e2e 页签用例守护 |
