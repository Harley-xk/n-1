# ADR-005：数据库迁移策略

- 状态：已接受
- 日期：2026-09-28
- 关联：[ADR-001](ADR-001-菜单与路由的权限承载方式.md)（同源哲学）；[架构设计](../架构设计.md)（迁移纪律）

## 背景

候选形态：TypeORM 内置 migration（TypeScript）/ 纯 SQL 手写（Flyway 风格）/ 独立迁移工具。判定标准：**哪种对 AI 生成最友好**。

## 决策

**TypeORM 内置 migration，TypeScript 形态，`migration:generate` 自动生成为主**：

1. **实体是 schema 的唯一事实源，迁移是自动 diff 的派生物**：`migration:generate` 对比实体与上次迁移快照，自动生成变更代码。
2. 手写迁移仅保留给数据变更与种子场景（如 admin 初始用户）；种子随迁移承载，不引入独立 seed 框架。
3. 命令挂 pnpm scripts（`migration:generate` / `migration:run` / `migration:revert`）；生产禁用 `DB_SYNC`，以 `migration:run` 建表与升级。

## 理由（AI 友好性论证）

| | TypeORM migration + generate | 纯 SQL 手写（Flyway 式） |
| --- | --- | --- |
| 事实源 | 实体（schema 声明与 ORM 映射同源） | 实体 + DDL 两处维护 |
| AI 生成新模块 | 写实体 → 跑一条命令 → 审查生成物 | 写实体 + 手写 SQL → 人工对齐两处 |
| 失配风险 | 几乎无（派生物） | 实体与 SQL 不一致只能运行时暴露 |

1. **单一事实源**与 ADR-001 同哲学：开发期确定的 schema 严格以代码为事实源，AI 的工作收敛为"生成实体 + 一条确定性命令"。
2. **生成物可审查**：TS 文件内含显式 SQL，git 可 diff、人工可审、DBA 可读，保留了 SQL 交付件的审查属性。
3. **ORM 生态优势对位利用**：MyBatis 系手写 SQL 源于无 schema 同步概念；TypeORM 的 `generate` 能力是其生态独特优势，不利用即退化。

## 边界与纪律

- `generate` 依赖"上次快照 + 当前实体"的 diff，**开发库与快照不一致时会生成意外变更**——操作纪律（生成前核对 diff、禁止手改生成物后失同步）见 [架构设计](../架构设计.md)迁移纪律。
- 存量库首次接入时生成基线迁移。

## 影响

- [架构设计](../架构设计.md)"数据访问"节承载迁移体系表述。
- 后端 e2e 的 DataSource 打桩策略不变；真库链路（浏览器 e2e / 冒烟）以 `migration:run` 初始化。
