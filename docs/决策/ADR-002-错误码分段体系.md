# ADR-002：错误码分段体系

- 状态：已接受
- 日期：2026-09-28
- 关联：[统一响应与异常处理设计](../指南/统一响应与异常处理设计.md)；[新模块接入指南](../指南/新模块接入指南.md)（段位登记表）

## 背景

升级前的错误码为简单三段式：`0` 成功、`-1` 业务错误（`BusinessError`）、框架级错误取 HTTP 状态码数值。单模块阶段足够，但多业务模块并行后，`-1` 无法区分错误来源，错误码不可检索、不可按模块治理。当时业务为零，是契约变更的低成本窗口。

## 决策

**升级为三段式分段错误码**：

1. 结构：**模块段 + 子域段 + 序号段**三段数值组合，位数定稿为 **3 + 3 + 3**（九位整数）。
2. 成功码 `0` 保持不变；参数校验、未认证、无权限、系统异常等**全局通用错误**设全局段（形态见「实施定稿」）。
3. 每个业务模块在接入时登记自己的模块段位（system 模块领首段 `001`）；错误码定义以代码常量为唯一出处，业务抛错引用常量——与 ADR-001 同一哲学。
4. `BusinessError` 携带分段码，`ApiResponse { code, message, data }` 外壳不变。

## 理由

1. **模块化扩展**：错误码即模块资产，可读、可检索、可去重；新模块领段位即可平行扩展，无中心协调。
2. **AI 生成友好**：登记即唯一、编译期常量引用，AI 生成新模块时错误码段位是接入清单中的一项确定动作。
3. **前端可治理**：可按模块段做差异化提示与上报策略。

## 影响

- 改造面：`BusinessError`、`http-exception.filter`、前端 `http.ts` 解包判断、存量 spec 与《统一响应与异常处理设计》文档同步更新。
- 分段段位表（现行分配：通用 `000` / system `001` / demo `002`）见 [新模块接入指南](../指南/新模块接入指南.md)，新模块接入时登记。

## 实施定稿（2026-09-28）

- 位数：**3 + 3 + 3**，整体为九位整数，成功码 `0` 不变。
- 通用段形态：模块 `000` + 子域 `000`，序号段借用 HTTP 语义码（400 / 401 / 403 / 404 / 405 / 500…）——数值上恰等于序号段本身，框架级错误的 code 与改造前数值完全一致（存量契约零破坏）；`000-000-999` 为未分类业务错误默认码。
- 常量实现：`server/src/common/errors/error-code.ts` 的 `ErrorCode` 值对象 + `GlobalErrorCode` 常量表；`BusinessError` 的 code 选项收紧为 `ErrorCode` 常量引用（编译期唯一出处，杜绝裸数字）。
- 前端判定：`code !== 0` 即失败（分段码全为正整数，原符号语义失效）。
