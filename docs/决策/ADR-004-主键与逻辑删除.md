# ADR-004：主键与逻辑删除

- 状态：已接受
- 日期：2026-09-28
- 关联：[架构设计](../架构设计.md)（数据层公共基座）

## 背景

数据层基建前需定稿主键策略与逻辑删除形态。候选：雪花 BIGINT（JS 侧超安全整数需 string 化）、UUID、自增；逻辑删除候选：`deleted` 标记字段 + 查询过滤 vs TypeORM 原生软删。

## 决策

1. **主键 UUID**：`@PrimaryGeneratedColumn('uuid')`，PostgreSQL 原生 `uuid` 类型；接口契约中主键类型为 string。
2. **逻辑删除采用 TypeORM 原生软删**：`@DeleteDateColumn`（`deletedAt` 时间戳）+ `softDelete()` / `softRemove()`，查询自动过滤已删行。
3. 审计公共实体 `BaseEntity`：`id (uuid) / creator / createTime / updater / updateTime / deletedAt`，creator / updater 为 UUID 外关联，由 `EntitySubscriber` 自动填充。

## 理由

1. **全链路 string 无精度问题**：雪花 ID 需要"Long 自适应序列化 + 前端一律 string"横切契约，UUID 天然消解这一问题，少一条横切规则。
2. **无中心协调**：雪花需机器位分配与时钟纪律，UUID 无此依赖。
3. **TypeORM 一等支持**：主键生成与软删均为框架原生能力，无需手写全局查询过滤器，AI 生成实体时声明即生效。
4. 自增主键暴露业务规模且不利分布式插入，不取。

## 影响

- BaseEntity 与所有业务表外键类型（uuid）。
- 接口契约"主键为 string"约定。
