# ADR-008 部署工具链平台无关化

## 背景

n-1 定位为通用框架底座，下游项目的 CI/CD 平台与构建运行环境不可预知。此前 ADR-006 / ADR-007 及两份部署指南以特定 CI 平台（阿里云效）为默认撰写——流水线操作步骤、产物上传通道、主机组等平台专属概念进入了框架文档；且 ADR-007 将发布包直部署定为主方案、docker 降为备选。对使用其他 CI 平台的下游，平台专属描述是接入噪音；主备分层也让 docker 更合适的场景（已有容器设施、多机分发）被文档导向抑制。

## 决策

1. **docker 镜像与发布包直部署两种交付方案平级保留**，不分主次：按目标环境选型（对比表见两份指南开头的方案选型节）
2. **工具链与文档平台无关**：不指定 CI/CD 平台，流水线以通用三段形态描述（构建 → 产物归档 → 目标机执行部署脚本）；前端签名密钥一律经 CI 加密变量注入（`VITE_SIGN_SECRET`）
3. **构建脚本不预设特定构建环境**：`scripts/build-release.sh` 仅要求 node 22 + pnpm（缺失时自举安装同代版本），任意构建环境均可执行；文档不描述特定环境的构建场景

## 理由

- 通用底座的下游多样性是常态；某平台的操作细节（变量在哪配、产物怎么传）属于下游自己的接入文档，不应进入框架文档
- 两方案机制均已落地验证（发布包本地实跑全流程、docker 镜像构建链路完整），平级保留零额外成本
- 「构建 → 产物 → 部署脚本」三段形态在任何主流 CI 平台都能直接映射，无需为每个平台维护一份操作手册

## 影响

- ADR-006 / ADR-007 中的平台背景（云效、ACR）仅作历史决策记录保留，不再构成约束
- 《打包与部署指南》更名为《发布包打包与部署指南》，与《Docker 打包与部署指南》平级互引；`deploy/` 工具链脚本与配置注释同步中性化（执行逻辑不变）
- 各部署方案的服务器初始化、配置参考仍由对应指南承载；下游选定平台后的具体接入细节自行补充
