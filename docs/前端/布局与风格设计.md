# 前端布局与风格设计

> 状态：已定稿（2026-09-28）。本文档是 web 前端主布局架构与视觉风格的唯一设计依据，实现偏离设计时先改本文档再改代码。
> 底稿为 n-2 同名文档（见兄弟仓库 `docs/前端/布局与风格设计.md`）：**布局骨架与交互机制照搬，视觉层重新设计**（n-2 消化吸收规划 §3「结构照搬、视觉差异化」约束），本文视觉章节（§2.2 / §6）为 n-1 自有方案。

## 1. 背景与目标

n-1 前端当前只有两个示例页（首页 + 404），无布局系统、无主题机制、无多标签页。本次升级将其从「示例页」升级为「脚手架门面」：企业级后台的完整布局骨架 + 可被业务定制的扩展机制 + 明暗双主题。

目标：

1. 多标签页架构：打开 / 关闭 / 切换 / 固定首页、右键菜单（关闭其他 / 全部 / 左右侧）、刷新当前页、localStorage 持久化恢复
2. 顶栏为一整条（品牌区 + 工具区 + 用户区），侧栏支持手动收起（开关在侧栏底部）与窄屏自动收起，状态持久化
3. 组件槽位注册表：业务可注册组件覆盖框架指定槽位，框架提供默认实现兜底
4. 暗色模式：设计 token 全量 CSS 变量化，明暗双套
5. 视觉走「青碧卡片浮起」路线：近纯色浅灰画布 + 白色卡片分区（侧栏独立卡片、标签栏与内容卡连体），主色青碧 `#0D9488`，10px 圆角、舒适密度——与 n-2 的「彩色渐变画布 + 透明悬浮 + 毛玻璃」质感明确区分

## 2. 布局架构

### 2.1 结构总览

```
body（画布 #F3F5F7，100vh，overflow:hidden，暗色 #101318）
└── .n1-app-wrapper                flex column，高度 100vh，四边内边距 12px
    ├── .n1-header                 顶栏一整条，56px，透明无底色（浮于画布）
    │   ├── 槽位 layout:logo       品牌区（默认：logo 方块标 + 系统名）
    │   ├── （弹性空隙）
    │   ├── 槽位 layout:header-tool 工具区（默认：主题切换按钮）
    │   └── 槽位 layout:header-user 用户区（默认：访客展示，批次四接认证）
    └── .n1-main-container         flex row，间距 12px，高度 calc(100vh - 56px - 12px)
        ├── .n1-sidebar            侧栏白卡片：220px / 收起 48px，圆角 10px + 1px 边框 + 浅阴影
        │   ├── el-scrollbar + el-menu（el-menu 保留，role=menubar 契约）
        │   │   └── SideMenuItem 递归渲染（目录 / 菜单，hidden 节点不渲染）
        │   └── .n1-sidebar-bottom 底部区
        │       ├── 槽位 layout:sidebar-bottom（默认：无）
        │       └── 收起开关       切换侧栏收起（收起态仅图标居中）
        └── .n1-content-layout     flex:1，flex column
            ├── .n1-tags-bar       标签栏 38px，白底 + 1px 边框（左右上三边），上圆角接内容卡片
            │   ├── 槽位 layout:tagsbar-left（默认：无）
            │   ├── 页签列表（横向滚动，隐藏滚动条）
            │   └── 槽位 layout:tagsbar-right（默认：刷新按钮 + 快捷关闭下拉）
            └── .n1-content-card   内容白卡片：圆角下 10px，左右下三边 1px 边框，唯一滚动容器
                └── RouterView + KeepAlive（缓存策略见 §3.4）
```

要点：

- **logo 在顶栏**，侧栏退化为纯菜单容器；顶栏因此可以做成一整条
- 顶栏透明浮于画布；**侧栏是独立白卡片**、标签栏 + 内容卡是连体白卡片（标签栏 `border-bottom: none`、内容卡只留左右下圆角，二者拼为一张视觉卡片）——与 n-2「全透明 + 毛玻璃」的悬浮质感形成差异
- 页面级滚动只发生在 `.n1-content-card` 内部（el-scrollbar），侧栏菜单独立滚动
- 404 页不进主布局（挂根级路由）

## 3. 多标签页设计

### 3.1 视觉形态

标签栏位于内容卡片正上方（非通栏、非顶栏下方），白底 + 细边框，与内容卡片视觉连成一体。页签为**圆角浅底块**形态：激活页签主色浅底（`--n1-color-primary-bg-light`）+ 主色文字 + 500 字重 + 全圆角 6px；非激活页签透明底 + 次级文字，hover 浅灰底。非首页页签 hover 显示关闭按钮；首页页签固定（无关闭按钮）。关闭当前页签时自动激活**左侧相邻**页签（无左侧则取右侧，全空则回首页）。

页签标题**前置菜单图标**：图标取 `route.meta.icon`（路由静态注册时的语义名），经 `utils/menu-icon` 映射为 Element Plus 图标组件——与侧栏共用同一张映射表与同一兜底（未命中落 `Menu`）。未激活签图标弱化为 `--n1-text-3`，hover 与激活签随主色，不盖过标题文字。隐藏子页（详情页等自身无图标的路由）**上溯最近一级带图标的路由**；首页固定签用保留语义名 `home`（`HomeFilled`，不进菜单候选）。图标不落持久化语义——恢复页签时按当前路由表重算，路由换图标后自动跟上。

### 3.2 数据模型

```ts
interface TagView {
  fullPath: string; // 唯一标识（path + query），同 path 不同 query 视为不同页签
  path: string;
  title: string; // 取 route.meta.title，兜底 '未命名'
  icon?: string; // 菜单图标语义名（meta.icon），渲染为标题前缀图标；缺失时留空由渲染侧兜底
  name?: string; // 路由 name（PascalCase），keep-alive 缓存键
  query: LocationQuery; // 恢复页签时回带
  affix: boolean; // 固定页签（首页），不可关闭
  keepAlive: boolean; // 是否参与 keep-alive 缓存
}
```

- 页签粒度：**fullPath 一签**。支持「同一列表页按不同 query 开多签」（详情页模式的预留）
- 固定页签：v1 仅首页 `/home`

### 3.3 状态与操作（Pinia：`stores/tags-view.ts`）

| 操作                                              | 行为                                                                   |
| ------------------------------------------------- | ---------------------------------------------------------------------- |
| `addView(route)`                                  | 路由 afterEach 调用；fullPath 去重后追加；affix 首页首次进入即落       |
| `closeTab(fullPath)`                              | 删除页签；若为当前激活签，跳转左侧相邻（无则右侧，再无则首页）         |
| `closeOthers / closeLeft / closeRight / closeAll` | 右键菜单动作；始终保留 affix 签；closeAll 后回首页                     |
| `beginRefresh(view)`                              | 见 §3.5（跳转动作由 `useTagsActions` 编排）                            |
| `cachedNames`（computed）                         | 打开中且 `meta.keepAlive` 的页签 `name` 集合，驱动 KeepAlive `include` |
| 持久化                                            | 每次变更写 localStorage（key `N1_TAGS`；批次四接认证后随登出清空）     |

### 3.4 keep-alive 缓存策略

**缓存跟随页签**——`KeepAlive :include` = 当前打开页签中 `meta.keepAlive` 的 `name` 集合。页签关闭即释放缓存，页签重开重新挂载。三方对齐关系：路由 `name` ↔ 页面 `defineOptions({ name })` ↔ 缓存名单，路由 name 一律 **PascalCase**（`Home` / `Redirect` / 业务页驼峰大写）。

### 3.5 刷新当前页机制

KeepAlive 的 include 变化只会清理**缓存**，不会重挂载**当前激活**实例，因此刷新经 redirect 中转路由配合缓存排除实现：

1. store 置 `refreshingName = 当前页签 name`，`cachedNames` 计算排除该 name
2. 跳转 `/redirect` + 原路径（`Layout` 下的静态子路由 `redirect/:path(.*)*`，meta `noTag` 不落签）→ 页面组件卸载时因 name 不在 include 中**不进缓存、直接销毁**
3. `RedirectView` 挂载即携带原 query `replace` 回原址 → 组件重新挂载，拿到全新实例
4. 回址的 `addView` 落地时清 `refreshingName`，缓存名单恢复

### 3.6 持久化恢复

- 恢复时机：首次导航成功时（guard afterEach 内标记），当前为全静态路由无时序问题；批次四接权限过滤后须在权限信息就绪后恢复
- 恢复校验：逐签 `router.resolve(path)`，仅保留能解析到 Layout 内非 404 路由的页签；激活签恢复失败则激活首页
- 存储内容不含组件实例，仅 §3.2 的纯数据字段

## 4. 侧栏收起

- **手动收起**：侧栏底部收起开关（与菜单项同规格行按钮）切换，状态入 app store 并持久化（localStorage）；收起态开关退化为居中图标
- **自动收起**：`matchMedia('(max-width: 992px)')` 监听（app store 内统一挂 / 卸），窄屏时无论手动状态如何一律收起；恢复宽屏时回到手动状态。**不做抽屉遮罩形态**（企业桌面后台定位，收起即图标模式，与手动收起同形态）
- 收起态：`el-menu :collapse` 原生能力，仅图标 + tooltip 弹出二级；菜单项去层级内边距、图标水平居中
- 生效值：`effectiveCollapsed = narrowScreen ? true : manualCollapsed`

## 5. 组件槽位注册表（业务覆盖机制）

### 5.1 机制

框架枚举**可覆盖槽位**（有限、可盘点、文档化），业务在应用挂载前调用注册函数替换槽位组件；未注册的槽位渲染框架默认组件（或空）。布局内所有槽位经统一的 `SlotRenderer` 渲染：

```
业务（main.ts 挂载前）──registerComponentOverride(key, comp)──▶ 槽位注册表（shallowReactive Map）
布局模板 ──<SlotRenderer name="layout:logo" :fallback="DefaultLogo" />──▶ 覆盖组件 ?? 默认组件
```

- 注册表 `shallowReactive`：支持挂载后注册（如异步块内），插入即触发重渲染
- 重复注册同一槽位：开发环境 console.warn，后注册者生效（幂等覆盖）
- 未知 key：类型层面由字面量联合类型拦截，运行时再兜一次 warn

### 5.2 槽位清单（v1）

| 槽位 key                | 位置                         | 默认组件                              | 典型业务用途                 |
| ----------------------- | ---------------------------- | ------------------------------------- | ---------------------------- |
| `layout:logo`           | 顶栏左侧品牌区               | logo 方块标 + 系统名                  | 换品牌 / 多租户标识          |
| `layout:header-tool`    | 顶栏右侧工具区（用户区左侧） | 主题切换按钮                          | 全局搜索、通知、帮助入口     |
| `layout:header-user`    | 顶栏最右用户区               | 访客展示（批次四升级为用户下拉 + 退出） | 扩展个人菜单               |
| `layout:sidebar-bottom` | 侧栏底部（收起开关之上）     | 无                                    | 组织切换、服务电话等常驻信息 |
| `layout:tagsbar-left`   | 标签栏左侧                   | 无                                    | 面包屑、常用功能快捷入口     |
| `layout:tagsbar-right`  | 标签栏右侧                   | 刷新当前页 + 快捷关闭下拉             | 标签栏功能扩展               |

新槽位由框架按需增补（改 keys 常量 + 布局模板 + 本表）；**业务不得绕过注册表直接改布局组件**。

### 5.3 业务接入示例

```ts
// 业务工程 main.ts（挂载前）
import { registerComponentOverride } from '@/framework/slots'
import BizLogo from './overrides/BizLogo.vue'

registerComponentOverride('layout:logo', BizLogo)
```

## 6. 视觉风格与设计 token（n-1 自有方案：「青碧卡片浮起」）

### 6.1 token 组织

全部视觉常量收敛为 `--n1-*` CSS 变量，明暗双套定义于 `styles/tokens.css`（`:root` 浅色、`html.dark` 深色），业务组件只允许消费 token、不允许硬编码色值。Element Plus 主题以 `--el-*` 变量覆写方式对齐（`styles/element-overrides.css`），不引入 sass。

### 6.2 色板（浅色基准）

| 类别             | token                       | 值                                       |
| ---------------- | --------------------------- | ---------------------------------------- |
| 主色             | `--n1-color-primary`        | `#0D9488`（青碧 teal-600）               |
| 主色悬停         | `--n1-color-primary-hover`  | `#0F766E`（加深）                        |
| 主色按下         | `--n1-color-primary-active` | `#115E59`                                |

| 弹层阴影         | `--n1-shadow-popup`         | `0 8px 24px rgba(15, 23, 42, 0.12)`      |

暗色套：主色提亮为 `#14B8A6`（teal-600 在深底可读性不足）、hover `#2DD4BF` / active `#5EEAD4`（提亮）、画布 `#101318`、卡片 `#1A1D23`、卡片边框 `#2A2F3A`、文字 `#E7EBF0` / `#A6B0C0` / `#6B7688`、分割 `#242932`、主色浅底 `rgba(20, 184, 166, 0.16)`。

与 n-2 的差异要点（视觉差异化落点）：

| 维度     | n-2                        | n-1                          |
| -------- | -------------------------- | ---------------------------- |
| 画布     | 四段彩色渐变（蓝紫粉）     | 近纯色浅冷灰                 |
| 侧栏质感 | 透明浮于画布               | 独立白卡片（边框 + 阴影）    |
| 标签栏   | 毛玻璃（半透明 + blur）    | 白底实色 + 细边框            |
| 主色     | `#2370EF` 亮蓝             | `#0D9488` 青碧               |
| 圆角     | 6px 紧凑                   | 10px（卡片）/ 6px（控件）    |
| 密度     | 紧凑（菜单 40px）          | 舒适（菜单 44px、顶栏 56px） |

### 6.3 Element Plus 覆写映射（`--el-*`）

- `--el-color-primary` 及 light-3/5/7/8/9、dark-2 全刻度对齐主色（浅色混白 / 暗色混黑，硬编码计算值，不用 color-mix）
- **EP 变量覆盖层位坑**：部分 `--el-table-*` 变量定义在 `.el-table` 组件元素上（非 `:root`），th 等子元素经 CSS 继承取最近层定义，`html` 层覆盖会被遮蔽——表格类变量必须同在 `.el-table` 选择器层覆盖（表头底色经 `--n1-table-header-bg` token 明暗自动翻转）；`--el-menu-*` 等定义在 `:root` 的变量不受影响
- `--el-border-radius-base: 6px`、菜单高度 / 内边距见 overrides 文件
- 字体栈：`system-ui, -apple-system, 'Segoe UI', Roboto, 'PingFang SC', 'Microsoft YaHei', sans-serif`

### 6.4 滚动条

全局 6px 扁平半透明滚动条（`::-webkit-scrollbar`），暗色下调低透明度；标签栏页签列表隐藏滚动条（滚轮横向滚动）。

## 7. 暗色模式实现

- 开关：`layout:header-tool` 默认组件提供三态切换（浅色 / 深色 / 跟随系统），el-dropdown 呈现
- 生效：`document.documentElement.classList.toggle('dark')`；跟随系统经 `matchMedia('(prefers-color-scheme: dark)')` 监听
- Element Plus 暗色：main.ts 引入 `element-plus/theme-chalk/dark/css-vars.css`
- 持久化：app store 内随设置落 localStorage（key `N1_APP`，含主题与侧栏收起）
- 业务页面只用 EP 组件与 `--n1-*` token，暗色自动生效

## 8. 路由与菜单（n-1 静态路由形态，ADR-001）

n-2 侧栏菜单来自后端菜单表；n-1 按 [ADR-001](../决策/ADR-001-菜单与路由的权限承载方式.md) 采用**代码静态路由 + 过滤生成菜单**：

- 路由结构：`/login`（批次四）与 `/:pathMatch(.*)*`（404）挂根级；`/`（name `Layout`，redirect `/home`）挂主布局，业务页面全部为其静态子路由（按模块拆文件注册，批次四落地）
- 菜单生成：`utils/menu.ts` 从 Layout 子路由树构建 `MenuNode[]`（path / title / icon / hidden / children），侧栏递归渲染；`meta.hidden: true` 的路由不进菜单（隐藏子页，如详情页）
- 图标语义：路由 `meta.icon` 存语义名（如 `system` / `user`），经 `utils/menu-icon.ts` 映射为 EP 图标组件，未命中兜底 `Menu` 图标
- 批次四接入权限后，菜单生成层加 `meta.permission` 过滤，布局组件零改动
