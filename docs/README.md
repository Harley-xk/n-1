# 开发文档

本目录集中维护 n-1 的全部开发文档，与代码同仓库、同版本演进。**所有文档使用中文撰写，目录与文件名使用中文命名。**

> 按仓库规则（[rules/base.md](../rules/base.md)），业务开发**文档先行**：先写设计文档，再写代码；实现偏离设计时，先更新文档再改代码。

## 目录规划

按**模块和功能**分门别类组织：

```text
docs/
├── README.md          # 文档导航（本文件）
├── 架构设计.md         # 全局性技术架构
├── 指南/              # 开发指南（专题向导：模块开发、测试、部署等）
├── 决策/              # 架构决策记录（ADR，每条重大决策一个文件）
└── <模块名>/           # 业务模块设计文档（「文档先行」规则的落点）
    └── <功能>设计.md   # 例：用户模块/登录功能设计.md
```

## 设计文档建议结构

业务功能设计文档建议包含：

1. **需求背景**：要解决什么问题、给谁用
2. **方案设计**：交互流程、接口约定、数据模型、关键实现思路
3. **边界与异常**：异常场景、权限边界、兼容性考虑
4. **验收标准**：完成的判定条件

## 撰写约定

1. 文档与代码同步更新：涉及架构、目录、约定变更时，必须同步修改对应文档
2. 一个主题一个文件，避免单文件过长
3. 重大技术选型请在 `决策/` 下补充 ADR（背景 → 决策 → 理由 → 影响）
