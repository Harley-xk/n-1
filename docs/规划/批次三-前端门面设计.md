# 批次三设计：前端门面（布局 / 主题 / 多标签页 / 槽位）

> 状态：已定稿（2026-09-28）。本文档是批次三实施的总纲，视觉与布局细则见 [布局与风格设计](../前端/布局与风格设计.md)（下称《布局设计》）。

## 1. 背景与范围

批次三对应 [n-2 消化吸收规划](n-2消化吸收规划.md) 批次三条目，将 n-1 前端从「两个示例页」升级为「脚手架门面」：

| 条目 | 内容 | 出处 |
| --- | --- | --- |
| A1 | 布局系统（顶栏一整条 / 可收起侧栏 / 标签栏 / 白卡片内容区） | n-2 `layouts/default/` |
| A2 | 设计 token 明暗双套 + 三态主题 + 992px 断点自动收起 | n-2 `styles/` + `stores/app.ts` |
| A3 | 多标签页（fullPath 一签 / 右键批量关闭 / redirect 刷新 / 持久化恢复） | n-2 `stores/tags-view.ts` + `views/redirect/` |
| A4 | 组件槽位注册表（6 槽位 + 业务覆盖 + 默认件兜底） | n-2 `framework/slots/` |
| A8 | 工具件（时间戳格式化 / storage 封装 / 菜单图标映射 / PlaceholderView） | n-2 `utils/` + `components/` |
| 决策 6 | 依赖版本升级至 n-2 同代（随本批次合并执行，避免搬运后二次返工） | 规划 §7 决策表 |
| C2 | n-1 版《布局与风格设计》文档落地（视觉方案重新设计） | 《布局设计》 |

**视觉定稿**：「青碧卡片浮起」方案（2026-09-28 与用户对比三候选后拍板）——近纯色浅灰画布 + 白色卡片分区（侧栏独立卡片、标签栏与内容卡连体）、主色 `#0D9488`、10px 圆角、舒适密度；骨架（四区结构 + 槽位 + 收起 + 多标签机制）与 n-2 一致。

### 2.2 配套配置改造

- **eslint.config.js 重写**：采 n-2 已在 ESLint 10 下验证的形态——`.vue` 文件显式 `vue-eslint-parser` + TS 子解析器（**ESLint 10 下 plugin-vue 的 processor 形态不生效，必须以 parser 方式接入**）；`@stylistic` 由 `configs.customize` 改逐条规则；保留 n-1 特有规则（`vue/multi-word-component-names` ignores `App`、`import-x/newline-after-import`）
- **tsconfig 三件改自写形态**（照 n-2）：TS 6 下放弃 `@vue/tsconfig` / `@tsconfig/node22` 基座，`tsconfig.app.json` 自带完整 `compilerOptions`（`verbatimModuleSyntax` / `strict` / bundler 解析），**spec 文件纳入 app 项目类型检查**（不再 exclude）
- **vite.config.ts**：`defineConfig` 改从 `vite` 导入 + `/// <reference types="vitest/config" />`（n-2 同款形态）；端口 / 代理 / test 配置不变
- **script 缩进规约变化**：`.vue` 的 `<script>` 内容从「相对 script 标签缩进一层」改为顶格（@stylistic/indent 统一 2 空格），存量 HomeView.vue 由 `pnpm lint --fix` 自动重排

### 2.3 升级风险与对策

- 大版本破坏性变更不可穷举——对策：**所有升级目标版本与 n-2 现网版本完全一致**，且 eslint / tsconfig / vite 配置直接采 n-2 已验证写法；升级后以 `pnpm check`（lint + vue-tsc + vitest）+ 浏览器 e2e 全量回归兜底
- 升级与布局改造**同一批次但分两步执行**：先升依赖 + 配置改造并跑全量检查（存量代码零业务改动下验证工具链），再落布局代码——工具链问题与业务问题分层定位

## 3. 移植适配决策（n-2 → n-1 差异点）

| # | 差异点 | n-2 形态 | n-1 适配 | 理由 |
| --- | --- | --- | --- | --- |
| 1 | 命名前缀 | `--n2-*` token / `.n2-*` class | `--n1-*` / `.n1-*` | 自有命名，规划 §3 A2 约定 |
| 2 | 持久化 key | `N_APP` / `N_TAGS` | `N1_APP` / `N1_TAGS` | 同上 |
| 3 | 菜单数据源 | 后端菜单表 → 动态 addRoute | **静态路由树 → `utils/menu.ts` 生成菜单**（Layout 子路由递归转 MenuNode，`meta.hidden` 过滤） | ADR-001：菜单不落库 |
| 4 | SideMenuItem 消费类型 | `MenuVO`（后端菜单 VO） | `MenuNode`（本地接口，由路由树转换） | 与 vue-router 类型解耦，批次四权限过滤在转换层做 |
| 5 | 用户区默认件 | auth store 昵称 + 退出登录 | 访客展示（静态「访客」头像文字，无下拉动作），保留 `.user-entry` 根类 | 批次三无认证；批次四接 auth store 升级 |
| 6 | 守卫 | 登录校验 + 动态路由注册 + 权限加载 + 页签 | 仅 afterEach（页签落地 / 持久化恢复 / 页面标题）；**beforeEach 认证链路批次四再加** | 循序渐进，避免无认证时空守卫 |
| 7 | 页签恢复校验 | Layout 内 + 非 public + 非 404 | Layout 内 + 非 404（public 概念批次四引入） | 当前无公开页 |
| 8 | 路由 name 规约 | PascalCase（Home / NotFound / Layout） | 对齐采 PascalCase（存量 `home` / `not-found` 改名） | keep-alive 缓存键 = 路由 name，三方对齐契约（《布局设计》§3.4） |
| 9 | RouteMeta | title / icon / hidden / keepAlive / noTag / public | 增补 icon / hidden / keepAlive / noTag（public 批次四） | 菜单与页签机制所需 |
| 10 | 图标映射表 | 16 语义名（n-2 全部菜单） | 裁剪为本规划内即将消费的集合（home / system / user / peoples / dept / post / dict / config / operate-log / login-log / doc / demo） | 避免无消费方的死映射 |
| 11 | 卡片扁平化 query-form 类 | `.n2-query-form` 列表页查询栏形态 | **不搬**，批次五随系统管理列表页落地 | 无消费方不预置 |
| 12 | 首页路径 | `/home`（Layout redirect） | 同 n-2：`/` redirect `/home`；e2e `goto('/')` 断言不变 | 页签 HOME_PATH 契约 |
| 13 | 演示页 | 61 个真实业务页承载验证 | 新增「组件演示」组两页（缓存演示 / 页签演示，§4） | 多标签与 keep-alive 需可操作载体；批次六由正式样板模块吸收 |

## 4. 演示页设计

挂「组件演示」目录（`meta.icon: demo`）下两页，全部走标准路由 + 菜单 + 页签链路：

1. **缓存演示** `/demo/cache`（name `DemoCache`，`meta.keepAlive: true`）：页面内局部计数器 + 「挂载时间戳」，验证切签缓存保留、关签 / 刷新后重建
2. **页签演示** `/demo/tabs`（name `DemoTabs`）：按钮以 `?tab=N` query 打开自身多签，验证 fullPath 一签粒度与右键批量关闭

演示页为脚手架展示件（等同首页 Pinia 示例定位），非测试专用代码；批次六样板模块落地后吸收替代。

## 5. 实施步骤

1. **依赖与工具链升级**：改 `web/package.json` → `pnpm install` → 重写 eslint.config.js / tsconfig 三件 / vite.config.ts → `pnpm lint --fix` 重排存量缩进 → `pnpm check` 全绿（存量零业务改动）
2. **基础件**：utils（storage / menu-icon / format / menu）/ styles 三件（token 取值按《布局设计》§6）/ PlaceholderView / framework/slots
3. **状态层**：stores/app + stores/tags-view（含 spec）
4. **布局层**：layouts/default 全套 + router 改造（Layout 壳 / redirect 子路由 / guard）+ main.ts / App.vue
5. **页面适配与演示页**：HomeView 迁移 / NotFoundView token 化 / demo 两页 / redirect 中转页
6. **e2e**：存量 3 用例回归 + 新增「布局与多标签」「主题切换」用例
7. **文档回填**：CLAUDE.md 当前状态、规划批次三勾选、架构设计文档（前端依赖与样式组织章节）

## 6. 验收标准

- `pnpm check` 全绿（ESLint 10 / vue-tsc 3 / vitest 5 下）
- 浏览器 e2e：存量 3 用例（首页展示 ×2 + 后端连通性 ×1）不回归；新增布局 / 多标签 / 主题用例通过
- 视觉抽查：浅 / 深两态下布局符合《布局设计》§6（青碧主色、卡片分区、无渐变无毛玻璃）
- 文档同步：本设计文档 + 《布局设计》与实现一致
