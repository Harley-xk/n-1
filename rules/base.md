# AI 工作规则 —— 基础约定（最高优先级）

> 本文件是所有 AI 规则中优先级最高的基础约定。任何其他规则、历史代码风格或临时指令与本文件冲突时，**以本文件为准**。
> 适用范围：本仓库内所有由 AI 参与的开发工作（含文档撰写）。

## 1. 文件头部注释（仅限代码文件）

**只有代码文件需要署名**；配置文件、测试文件、资源文件等**不需要**携带头部注释。

需要署名的文件（业务源代码）：

- `.ts` / `.js` / `.mjs` / `.cjs` / `.vue` 等业务源码（页面、组件、路由、状态、服务、工具等模块）

不需要署名的文件：

- **配置文件**：`.json` / `.yaml` / `.yml` / `.env*` / `.gitignore` / `.gitattributes` / `*.config.*` / `tsconfig*` 等
- **测试文件**：`*.spec.ts` / `*.test.ts` / `test/**` 等各类测试
- **资源文件**：样式（`.css` 等）、图片、字体、HTML 入口、类型声明（`*.d.ts`）等

需要署名的代码文件，必须在文件首行携带如下格式的头部注释：

```js
/*
 * 作者: Harley-xk
 * 创建: 2026-06-15
 *
 * 描述: 当前文件的描述
 */
```

字段说明：

| 字段 | 说明 |
| --- | --- |
| 作者 | 当前操作用户名 |
| 创建 | 文件创建日期，格式 `YYYY-MM-DD` |
| 描述 | 用一句话概括当前文件的职责或用途 |

## 2. 注释语法按语言适配

头部注释的语法必须与文件实际使用的语言匹配：

| 文件类型 | 注释语法 |
| --- | --- |
| `.ts` / `.js` / `.mjs` / `.cjs` / `.cts` / `.mts` / `.css` / `.scss` / `.less` | `/* ... */` 块注释 |
| `.vue` / `.html` | `<!-- ... -->`（置于文件首行） |
| `.py` / `.sh` / `.yaml` / `.yml` / `.properties` / `.env` / `.gitignore` | 每行以 `#` 开始 |
| `.json` | JSON 标准不支持注释，跳过头部注释 |
| `.md` | 文档文件，不强制携带头部注释 |

## 4. 文档先行

所有业务开发必须**文档先行**：先写设计文档，再实际写代码。

1. 任何业务模块 / 功能开发前，先在 `docs/` 下编写对应的设计文档（需求背景、方案设计、接口约定、数据模型等）
2. 文档统一放在 `docs/` 目录下，**按模块和功能分门别类**组织目录，如 `docs/用户模块/登录功能设计.md`
3. 文档（目录与文件名）一律使用**中文命名**
4. 代码实现与文档保持同步：实现偏离设计时，先更新文档再改代码

## 5. 完成定义（DoD）

任何代码改动（含 AI 生成）视为「完成」，必须同时满足：

1. 根目录 `pnpm check` 全部通过（ESLint 修复 + 类型检查 + 单元测试 + 后端 API e2e 测试）
2. git 提交时 pre-commit 钩子（lefthook）对暂存文件的自动检查通过
3. 实现偏离设计或涉及接口 / 数据模型变更的，已按「文档先行」先更新文档
4. 涉及前端页面交互的功能，优先在 `e2e/` 包下补充 Playwright 验收脚本

## 6. 提交信息规范

git 提交信息统一使用固定格式：

```text
【动作】模块 - 内容概述
```

| 字段 | 约定 |
| --- | --- |
| 动作 | 以两个字为主：新增 / 修改 / 修复 / 移除 / 重构 / 优化 等 |
| 模块 | 改动所属子包或业务模块：`server` / `web` / `e2e` / `文档` / `工程化` / `用户模块` 等 |
| 内容概述 | 一句话说明本次改动要点 |

示例：`【新增】用户模块 - 登录接口与 JWT 鉴权`

格式由 commit-msg 钩子（lefthook + `scripts/verify-commit-msg.mjs`）在提交时自动校验；合并、还原等自动生成的提交不受限制。
